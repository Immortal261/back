# FlexarPPF — интернет-магазин автомобильных плёнок

Каталог, корзина, оформление заказа с оплатой Kaspi Pay / картой, склад
с историей движения товара и админ-панель с аналитикой продаж.

## Требования

**Node.js 22.5 или новее.** Учёт остатков использует встроенный в Node.js
модуль `node:sqlite` — это значит НЕ нужно ничего компилировать (никаких
better-sqlite3/node-gyp), но нужна свежая версия Node. Проверить:

```bash
node --version
```

Если версия старше — обновите (например через nvm: `nvm install 22 && nvm use 22`).

## Запуск локально

```bash
npm install
cp .env.example .env
npm start
```

Магазин: `http://localhost:3000`
Админ-панель: `http://localhost:3000/admin/login.html`

При первом запуске в консоли будет выведен логин и пароль администратора
(если не задать `ADMIN_USERNAME`/`ADMIN_PASSWORD` в `.env` — пароль
сгенерируется случайно и покажется **только один раз**, сохраните его).
Чтобы задать свой пароль заранее — впишите его в `.env` до первого запуска.

Для разработки с автоперезапуском:

```bash
npm run dev
```

## Структура проекта

```
server/
  index.js              — точка входа Express
  db/index.js            — схема SQLite, миграция старых товаров, сид админа
  data/shop.db            — файл базы данных (создаётся автоматически)
  routes/
    products.js, cart.js, orders.js  — публичный API магазина
    admin.js                          — API админ-панели (требует авторизации)
  lib/
    cart.js               — корзина в памяти (привязана к cookie)
    order-service.js      — создание заказа, подтверждение оплаты со списанием
    inventory.js          — учёт остатков и история движения (склад)
    analytics.js          — аналитика продаж (выручка, топ товаров, графики)
    auth.js, password.js  — авторизация администратора
    payments/              — модули Kaspi Pay и оплаты картой
public/
  index.html, css/, js/   — витрина магазина (не изменена)
  admin/                  — админ-панель (логин + дашборд)
```

## Как теперь редактировать товары

Каталог переехал из `products.json` в базу данных (`server/data/shop.db`).
При первом запуске товары **автоматически переносятся** один раз из старого
`server/data/products.json` (файл можно после этого не трогать — он больше
не читается на лету). Дальше товары редактируются:
- через SQL напрямую (`sqlite3 server/data/shop.db`), либо
- добавьте в админку экран редактирования карточки товара, если понадобится
  (сейчас админка умеет менять только остаток — это было в ТЗ).

## Как работает склад

- У каждого товара есть `stock_quantity` — доступно **только администратору**,
  клиентам на сайте показывается лишь факт «в наличии / нет в наличии»,
  без точного числа.
- **Поступление/ручная корректировка** — кнопка «Изменить остаток» в админке,
  с обязательной причиной. Каждое изменение пишется в историю
  (`stock_movements`): что, сколько, когда, кто, привязка к заказу.
- **Списание при продаже** — автоматическое, но **только после подтверждения
  оплаты**. Поскольку реальная интеграция Kaspi/эквайринга у вас в режиме
  demo (см. ниже), подтверждение сейчас — кнопка «Подтвердить оплату» в
  админке на заказе. Она списывает остаток по всем позициям заказа одной
  транзакцией: если чего-то не хватает — операция откатывается целиком,
  заказ остаётся неоплаченным, ничего не спишется наполовину.
- Когда подключите реальный Kaspi/эквайринг — вебхук от провайдера должен
  вызывать ту же функцию `confirmOrderPayment(orderId)` из
  `server/lib/order-service.js`. Логику склада менять не придётся.

## Админ-панель

`http://localhost:3000/admin/login.html` — логин/пароль администратора
(см. вывод в консоли при первом запуске или ваши значения из `.env`).

Разделы:
- **Фильтры по периоду** — сегодня / вчера / 7 дней / 30 дней / текущий
  месяц / прошлый месяц / произвольный период.
- **Сводка** — выручка, количество заказов, продано штук, остаток на складе.
- **График** — выручка по дням за выбранный период.
- **Товары** — таблица «Товар / Остаток / Продано / Заказы / Выручка /
  Статус», кнопка «Изменить остаток», клик по названию — история движения.
- **Заказы** — список с составом и статусом, кнопки «Подтвердить оплату»
  (списывает склад) и «Отменить» (только для неоплаченных).

Доступ к данным проверяется **на сервере** (`requireAdmin` в
`server/lib/auth.js`) на каждом API-запросе — а не только скрытием кнопок
в интерфейсе, как и требовалось.

### Ограничение текущей авторизации (для MVP)

Сессии администратора хранятся в памяти процесса — при перезапуске сервера
нужно будет перелогиниться. Для одного администратора/небольшой команды
этого достаточно; если нужна персистентность между перезапусками — сессии
можно перенести в таблицу БД (архитектура это позволяет без переделки).

## Как добавить свои фото

**Свотчи «Глянец» и «Сатин»** — файлы `public/img/finish-gloss.jpg` и
`public/img/finish-satin.jpg`. Замена — просто перезапишите файлы с теми же
именами.

**Галерея примеров работ** — 4 файла в `public/img/gallery/`:
`1.jpg`, `2.jpg`, `3.jpg`, `4.jpg`. Формат jpg/png/webp — если не jpg,
поправьте расширение в `src=` в `public/index.html`.

## Про оплату Kaspi (по ссылке) и картой

**Kaspi Pay работает через вашу постоянную ссылку**, а не через API:

1. Получите в приложении Kaspi.kz ссылку на приём платежей на ваш счёт ИП
   (без фиксированной суммы — клиент вводит сумму сам).
2. Впишите её в `.env`: `KASPI_PAYMENT_LINK=https://...`
3. Готово — после оформления заказа на сайте покупателю сразу показывается
   сумма к оплате и кнопка «Оплатить через Kaspi Pay», ведущая по этой ссылке.
   Ссылка одна и та же для всех заказов, суммы она не подставляет — это
   осознанное упрощение по вашему решению, а не баг: клиент должен ввести
   сумму в Kaspi вручную.

Пока `KASPI_PAYMENT_LINK` не заполнена — работает прежний демо-режим
(инструкция «свяжитесь с клиентом и выставите счёт вручную»).

**Списание товара со склада** по-прежнему происходит не автоматически по
факту клика на ссылку (сайт не может знать, оплатил ли клиент на самом
деле), а только когда вы вручную нажмёте «Подтвердить оплату» в админке,
после того как увидите поступление в своём Kaspi. Это осталось без
изменений — см. раздел «Как работает склад» выше.

**Оплата картой** оставлена как второй вариант, в прежнем демо-режиме
(показывает инструкцию, реального эквайринга ещё нет). Если решите
подключить платёжный агрегатор (Epay/Halyk, CloudPayments, PayBox и т.п.)
для карт — впишите ключи в `CARD_PROVIDER`/`CARD_API_KEY`/`CARD_API_SECRET`
и замените заглушку в `server/lib/payments/card.js` на реальный вызов API,
сверяясь с официальной документацией провайдера.

## Прочие осознанные ограничения MVP

- Корзина — в памяти процесса (сбрасывается при перезапуске сервера,
  оформленные заказы при этом не теряются — они в БД).
- `server/data/orders.json` — старый файл, больше не используется (заказы
  теперь в `shop.db`), можно удалить.
- Мягкая проверка остатка при добавлении в корзину/оформлении — не резервирование.
  Если два покупателя одновременно закажут последнюю единицу, второй получит
  понятную ошибку на чекауте, а не «продажу в минус» (списание всё равно
  защищено транзакцией на уровне БД).
